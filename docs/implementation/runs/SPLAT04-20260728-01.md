## Architecture

`App` bypasses all front-door state for `/art-review/*`. Other routes initialize a
pure reducer with a route-specific loading destination:

- `/`: `loading -> home`
- first `/play/:slug`: `loading -> target-range -> arena`
- completed `/play/:slug`: `loading -> arena`

Onboarding completion is stored under versioned key `splat04.onboarding.v1`.
The online `GameWorld` and local onboarding `GameWorld` are separate. The range
`LocalGame` is constructed as stable render state before that screen can mount, rather
than relying on a ref plus an unrelated render. The network client begins during
loading; target-range completion no longer starts networking and has no timer escape.
A failed online connection reducer-transitions the arena to Practice and supplies a
concrete local simulation in the same React update.

The splash and home menu are distinct:

- `LoadingSplash` renders approved key art plus only real progress, status, and a
  minimum-playable Skip.
- `HomeMenu` renders a clean estate plate with real DOM controls. Coverage and local
  Practice are available. Coreball is visibly disabled as Coming Soon because no
  Coreball gameplay exists.

## Real loading instrumentation

`window.__splat04.loadingMetrics` records:

- app start
- first mounted splash
- image decode settlement
- network initialization
- runtime canvas creation
- minimum playable
- full asset completion
- full readiness

`window.__splat04.viceEstateAssets` records the selected device tier's URL list,
minimum/optional decoded events, per-event timestamps, resource-timing byte counts,
failure counts, and minimum/full ready timestamps.

The loader preserves the 31-source manifest inventory but requests one URL per
selected runtime path. Gameplay excludes the two static paint GLBs that dynamic
`PaintFloor` replaces; art review retains them. It does not preload both primary and
LOD alternatives. A failed required GLB keeps `minimumReady` false and gives the
overall load an error status.

The selected-path loader exposes separate `minimumReady` and `fullReady` promises.
`ViceEstateVisualLayer` mounts critical villas, fountain, ground and cover as soon as
the minimum promise succeeds, then appends optional placements once without clearing or
duplicating the minimum layer. `minimumPlayableAt` and `fullAssetsAt` are separate metrics.

Skip appears only after the minimum GLBs are successful and visibly mounted, the canvas
exists, networking has started, and the destination UI plate has settled, while optional
downloads are still running. Normal automatic completion waits for the full promise.
Root loading preloads and decodes the clean home plate in parallel.

Explicit `?renderer=legacy` never starts the GLB loader. A total or critical GLB failure
switches `GameScene` to the preserved procedural renderer and releases loading through
the same `legacy-ready` contract; optional-only failures remain a usable degraded GLTF
result.

Service-worker v3 registration now includes the matching page lifecycle: a waiting worker
receives `splat04:activate-update` only outside an active match, and the resulting
`controllerchange` reloads once.

## Frozen renderer boundary

The phased loading exception inside the previously accepted scene renderer is limited to
exactly two files:

- `ViceEstateVisualLayer.tsx` mounts critical placements first, appends optional
  placements without duplication, and exposes both a phase-aware gameplay callback and
  its original `loading | ready | error` art-review callback.
- `GameScene.tsx` forwards minimum/full readiness, reports explicit legacy readiness, and
  converts a critical GLB error to the established procedural fallback.

`ArtReviewScene.tsx` and `viceEstateMode.ts` remain byte-equivalent to HEAD `214e0a4`.
This exception changes loading boundaries and signaling only; it does not change visual
placements, transforms, materials, lighting, layout, collision, or legacy rendering.

## Known issues / honest gaps

- No clean transparent player/key-art asset exists. The home menu intentionally uses the
  clean estate plate without fabricating a replacement player.
- Coreball has no gameplay implementation, so it is disabled rather than presented as a
  working mode.
- Resource Timing may report zero transfer bytes for memory/disk/service-worker cache
  hits; the event log still records decoded URL completion and timing.
- Browser automation reached the real first-time TargetRange but did not reliably
  complete the pointer-lock exercise; reducer tests cover its same-session arena handoff.
- The first seeded v1 browser exercise exposed an installed-to-waiting race. The lifecycle
  now retries that handoff outside active matches and its regression test passes; a second
  seeded browser migration was not run after that final correction.
- Browser/Blender material parity is not claimed and was not changed here.
